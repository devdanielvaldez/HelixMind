# MedAI and AgentMesh architecture

## Responsibility split

| System | Owns |
| --- | --- |
| MedAI Rust core | Research-session identity and plans, evidence and graph persistence, content-hashed research artifacts, capability metadata, CLI, local API, provenance envelope |
| MedAI Python layer | PubMed, ClinicalTrials.gov, MyGene.info, UniProtKB, and Reactome adapters; bioinformatics, chemistry, statistics, model integrations, reproducible computational analyses |
| MedAI web | Research sessions, literature/evidence views, graph exploration, capability review, run provenance |
| AgentMesh | MCP discovery/routing, identity and policy enforcement, approvals, audit, capability package catalog, operational workflow execution |

## Request lifecycle

1. The Research Director validates the durable task DAG, verifies registered domains/dependencies, and assigns each task to a policy-scoped biomedical specialist. Its versioned, hash-addressed assignment manifest is retained with task outcomes.
2. Python workers enforce each specialist's MCP tool allowlist and can connect either directly to MedAI's authenticated MCP endpoint or through AgentMesh. Separate queue consumers use role-bound API credentials, specialist-specific model profiles, and persistent per-specialist session credit ceilings. The API validates the credential's scientific-agent identity against the assigned DAG task on claims, lease operations, task transitions, evidence, artifact, graph, and budget writes; a caller-supplied worker ID is not an identity.
3. Capability discovery searches verified catalog entries by intent and domain. A deterministic score is advisory; it never authorizes execution.
4. Existing authorized MCP capabilities are invoked through the configured MCP route. AgentMesh can add governed discovery and routing; direct worker execution uses MedAI's MCP transport token. External source adapters retain provider record IDs and retrieval metadata.
5. Scientific analysis runs in constrained Python/Rust worker profiles. Generated source code starts disabled and cannot be imported into the AgentMesh gateway.
6. Claims are stored separately from source records and interpretations. Graph edges must point to retained evidence.
7. A critic searches for contradictory evidence and alternative explanations before candidate hypotheses enter a report.
8. Reports retain the session, plan, sources, tools, versions, datasets, parameters, and timestamps needed to replay computational steps.

## Persisted task execution

Scientific HTTP adapters and the AgentMesh control-plane client use one decoded-byte streaming reader. It validates status and declared content length, then checks each decoded chunk against the remaining buffer allowance before appending it. This bounds retained response memory and stops reading at the first excess; each adapter still supplies its own source-specific size ceiling.

UniProtKB is available as a budgeted MCP source adapter and stores accession-linked protein annotation and sequence records with UniProt provenance.

PMC BioC protein annotations labeled `UniProt` or `UniProtKB` are linked to the same `UniProtKB:<accession>` graph identifier after strict accession-format validation. The source namespace and original accession remain in the entity metadata, and no protein node is inferred from a mention string. UniProt documents the 6/10-character accession patterns and stable accession usage in its [accession help](https://www.uniprot.org/help/accession_numbers).

Reactome gene-list analysis is available through the official Analysis Service. Each result artifact records the input identifiers and digest, species, retrieval time, and service output. Over-representation results describe pathway association and do not establish a causal mechanism.

ClinicalTrials.gov v2 search and NCT lookup return both a retained raw source record and a normalized snapshot of study status/dates, design, intervention, outcomes, eligibility text, sponsor, locations, retrieval time, and canonical record hash. Each snapshot includes a link to the official per-study record-history page. The official [REST API documentation](https://clinicaltrials.gov/data-api/about-api) describes access to the most recent study records; the [record-history UI](https://clinicaltrials.gov/study/NCT04548817?tab=history) displays historical versions, but the official API documentation does not document a machine-readable history endpoint. MedAI does not depend on undocumented internal routes, so automated comparisons remain limited to snapshots captured by MedAI. The adapter reports registry metadata only; it does not infer participant suitability, trial quality, or treatment advice.

UniProtKB provides accession-linked protein sequence/annotation records. The entry adapter also retains complete bounded records and extracts annotated domain/region features and PDB cross-reference metadata, with a canonical record hash. PDB cross-references are source metadata; residue-level mapping and experimental interpretation still require review of the linked structure record. The AlphaFold DB adapter retrieves the current predicted-model records from `alphafold.com` for a validated UniProt accession, preserves the provider payload/hash, and returns model/version IDs, sequence ranges, confidence summaries, and coordinate URLs. It follows the post-June-2026 response field names while tolerating legacy aliases. pLDDT describes local predicted confidence; it is not experimental structure evidence and does not independently validate inter-domain orientation or interactions.
`protein-mapping` combines PDB cross-references from the bounded UniProtKB entry with PDBe SIFTS per-entry XML. It retains per-residue UniProt and PDB sequence numbers, chain/entity IDs, author numbering, residue details, and SHA-256 for each uncompressed XML and updated mmCIF snapshot. `_pdbx_sifts_xref_db.observed` supplies explicit atomic-coordinate presence (`Y`/`N`); unavailable or ambiguous rows remain `unknown`. The lookup limits structures and source sizes and does not interpolate missing residue mappings.

IntAct interaction lookup uses the public PSICQUIC REST service and preserves each MITAB row, publication, detection method, biological participant roles, source interaction ID, organism identifiers, and source confidence string with a response hash. Reconciliation groups unordered pairs only when stable participant identifiers, taxa, and biological roles align; it reports exact duplicate rows, unique publication IDs, and method/type heterogeneity. It does not infer independent replication or combine provider scores. An independently adjudicated benchmark and cross-source conflict evaluation remain pending.

ClinVar retrieval uses bounded E-utilities ESearch/ESummary/EFetch VCV requests and stores selected variation summaries, precise GRCh37/GRCh38 single-allele locations, source-record hashes, stable variation/accession identifiers, and retrieval time. Local reconciliation requires a reference-validated genomic report and the exact FASTA whose digest it records; ClinVar locations and local calls are both normalized against that FASTA, and only exact assembly/contig/REF/ALT matches are linked. Composite haplotype/genotype records, uncertain locations, reference mismatches, and unsupported alleles remain unmatched. ClinVar significance fields represent classifications aggregated from submitters; reconciliation does not re-evaluate pathogenicity or provide clinical recommendations. Independent review of repeat-context and complex-variant mappings remains pending.

The local genomic parsers validate VCF structure, explicit GRCh37/GRCh38 assembly selection, coordinates, alleles, quality/filter fields, aggregate genotype dosage counts, FASTA records, and wrapped FASTQ sequence/quality lengths. With a local uncompressed reference FASTA, VCF REF alleles are checked and simple insertions/deletions receive minimal representation and left alignment; complex unequal-length alleles are explicitly marked as not left-aligned. Input/reference hashes are retained, sample and record names and raw sequences are omitted, and no network access occurs. FASTQ quality requires Phred+33. Optional local GFF3 projection maps validated alleles to transcript coordinates and translates protein consequences for supported nuclear/vertebrate mitochondrial codes; annotation hash and build directive are included. Annotated exons are also used to label canonical splice donor/acceptor bases and nearby splice-region positions using Ensembl's positional ranges; splice labels require overlap with those explicit positional windows and do not predict splice function. Introns are inferred only from annotated exon structure (or a gap between annotated CDS segments); a transcript span without exon structure is reported as `transcript_variant`. Explicit UTR annotations are retained, while ambiguous exonic noncoding overlap is not assigned an unsupported UTR or intron term. Versioned regression fixtures check negative-strand missense consequences, codons, CDS coordinates, and protein positions against Ensembl VEP's published examples. Positive-strand synthetic transcript regressions also cover start-lost, stop-gained, frameshift, in-frame insertion/deletion, missense, and synonymous consequences; these exercise local behavior but are not independent external validation. The annotation is a bounded local implementation, not full VEP parity, and it makes no pathogenicity or clinical claims.

`medai-science genome-vcf --bundle-dir DIR` produces a private replayable artifact containing the exact local inputs, report, parameters, runtime metadata, and hashed copies of the scientific source modules. Bundle creation refuses an existing target and checks input hashes again while copying. `bundle-verify DIR` validates artifact hashes; adding `--replay` reruns the analysis only if the installed Python version and source module hashes match the bundle. Replay does not execute bundled code and makes no network calls. Bundle integrity hashes detect accidental changes, but do not cryptographically authenticate a bundle's creator.

The final research report supplements task and source counts with a bounded bibliography of hash-verified PubMed metadata, graph relationships that have same-session evidence links, and the latest integrity-verified candidate-hypothesis proposal with its exact-payload-linked criticism. It shows evidence IDs, source IDs, and recorded polarity, privacy-screens entity/hypothesis/title labels, excludes abstracts and source claim bodies, leaves novelty unscored, and states that relationships are not causal findings and quality annotations are not calibrated.

The `trial NCT... --bundle-dir DIR` workflow captures a public ClinicalTrials.gov v2 record, its normalized representation, retrieval timestamp, and exact adapter source. Offline replay re-runs normalization from the retained source record and verifies that the installed adapter/runtime match; it does not access the network or assess study quality or clinical suitability.

The hypothesis service enumerates bounded simple directed paths of two to four edges in a single session graph and retains candidate artifacts with source evidence IDs for every edge. Every traversed edge must have at least one source-labeled supporting record; paths are capped at 50,000 traversals per proposal and the receipt reports truncation. Retained candidates are bounded to 1,024 unique evidence IDs and 96 KiB serialized each, with a 3 MiB aggregate candidate payload cap. Ranking-limit and byte-limit omissions are counted separately; before criticism or report generation, the retained artifact digest, byte counts, omission arithmetic, truncation flags, path continuity, per-edge evidence receipts, polarity-count shape, global evidence-ID reconciliation, and unscored novelty are revalidated. PubMed discovery binds three to five ordered path entities into one bounded query. It reports evidence counts, evidence-quality annotations, edge-confidence annotations, and the share of cited records marked contradictory as separate descriptive dimensions. Novelty remains `null` until a scoped literature comparator exists. The critic searches alternative source-linked routes matching the candidate path length under a 50,000 route-check ceiling, alongside linked contradictions, lexical evidence search leads, and methodological limitations; it reports route-search truncation and the worker sends incomplete proposal, literature, or critic work to human review. It does not issue an automated scientific verdict.

The `contradictions.search` worker stage can compare retained PMC result-annotation artifacts by exact shared BioC entity ID, matching result category, and opposite categorical direction. It stores only review candidates linked to the source annotation artifact, document ID, result candidate IDs, sentence-level document offsets and lengths, and content hashes. BioC sentence offsets remain document-relative; passage text candidates retain both the passage base offset and the sentence's local offset. Annotated entity locations are retained only when their exact text span can be checked against a known sentence/passage base offset. Entity IDs are canonicalized with their source namespace before model candidate screening and cross-paper comparison; annotations without a database namespace remain unresolved and are not merged by identifier alone. Pair comparisons and artifacts are bounded. A loopback model receives bounded title, abstract, and methods context only for exact operator-allowlisted article licenses; the artifact retains context hashes and categorical study-design, population, and method-family labels, never copied source text. Conflicting labels across batches abstain to unclear. The review panel compares these categories alongside broad human/animal/cell/computational labels, but they are unvalidated screening signals and matching labels do not establish comparability. These directional leads are not semantic claim alignment and are never recorded as confirmed contradictions.

Gene identifiers supplied by PMC BioC are resolved against MyGene.info using exact Entrez Gene identifiers. Only exact matches with a safe provider symbol become Reactome pathway inputs, and the Reactome over-representation result retains its input hash and source artifact. These annotations do not create gene–pathway causal edges; pathway analysis is an association result and the task is skipped when exact mappings are unavailable.

The protein worker stage selects exact human gene mappings within the session paper limit and remaining execution-credit budget. It searches UniProt with each provider symbol, accepts only returned records with the exact gene symbol and human taxonomy, then persists UniProt feature metadata, AlphaFold predictions, IntAct interaction observations, and SIFTS mappings when experimental PDB cross-references exist. It registers stable protein nodes with provenance but creates no biological edges without evidence records.

`medai protein-structure-analyze local.pdb` validates bounded fixed-column PDB coordinate records; `.cif` and `.mmcif` inputs use the optional Biopython `bio` extra. Both return input hashes plus model/chain/residue/alpha-carbon counts and per-chain sequence hashes. `--bundle-dir` captures the exact local coordinate file and parser implementation in a private bundle; `bundle-verify --replay` rechecks integrity and recomputes the summary offline only when the Python/parser versions match (and, for mmCIF, the Biopython version matches). Coordinates are not retained in the returned summary, generic temperature factors are not equated with AlphaFold pLDDT, and the summary does not claim protein identity, structural function, or binding. The bundle contains the coordinate input and should be handled as sensitive research data. Source metadata and reference-sequence reconciliation remain separate.

The Python research worker connects to the AgentMesh Streamable HTTP gateway using the MCP client SDK. Its one-shot and polling modes normalize objective whitespace, execute PubMed/Crossref/ClinicalTrials.gov discovery, and run a resumable literature extraction stage through AgentMesh tools. PubMed provider labels and DOI/PMC identifiers remain source-linked; unlabelled abstract sections stay unclassified. If PMC is available, the worker parses BioC and persists only a structural receipt, source hash, and stable entity identifiers; article passages and sentence candidates are not copied into session artifacts. NCBI Gene annotations are looked up through MyGene.info by Entrez ID, and only exact identifier matches enter the resolution receipt. Tasks without validated executors move to `needs_review`; the worker never reports unsupported analysis as completed. Public-source query checks reject common direct identifiers, though researchers must still ensure objectives contain no patient-identifying data. When a configured model is available, objective planning selects a bounded subset of registered DAG tasks, with mandatory evidence synthesis, criticism, and reproducibility stages. The scope artifact is hash-verified and bound to the session, objective, and depth. Excluded stages are completed as explicit AgentMesh `skipped` transitions; invalid or unavailable model plans retain the complete registered task set.
The Research Director applies a validated model task scope through `medai_research_apply_task_scope` while it still owns the live `objective.normalize` lease. The API and Rust store recheck the artifact hash, session objective/depth binding, registered task IDs, mandatory stages, and prerequisites in one SQLite transaction, then mark only queued unselected stages `skipped`. This occurs before specialist claims, so excluded work incurs no task-start credit. The MCP/API operation is restricted to the authenticated Research Director role.

Workers can atomically claim up to 16 ready tasks, each with a bounded lease and a budget charge. A specialist worker passes only its registered task IDs to the claim operation; `medai-science work --agent-id <specialist>` and the `agentmesh-specialist` Compose profile provide separate deployment modes. Each specialist process uses a unique lease owner, and the API independently checks its authenticated specialist identity against the task's DAG assignment. A live lease can be renewed only by the recorded owner; a leased task can only be completed by that owner before expiry. Recovery requeues expired work and marks it failed after five attempts. Claim, renewal, completion, and recovery are written to the task event log. These controls provide durable single-host task coordination; production still needs monitored queue operations and external security review.

Every session starts with domain tasks for objective normalization, literature and trial discovery, extraction, entity resolution, evidence grading, optional genomics/protein/pathway analysis, separate chemistry identity resolution and pharmacology analysis, contradiction search, graph construction, hypothesis proposal and criticism, and reproducible reporting. The chemistry specialist resolves source-identified PubChem identifiers; the pharmacology specialist consumes retained exact identities for ChEMBL lookup. The initial task is `ready`; dependent tasks are `blocked`. Session depth and an execution-credit ceiling are persisted. Task starts, bounded source operations, provider-reported model tokens, logical artifact payload bytes, measured isolated capability CPU time, and authenticated session-scoped API requests are charged. System/provider/GPU compute and physical storage overhead are not yet metered.

Task transitions are audited in `task_events`. Only `ready → running → succeeded|failed|needs_review` and the documented retry/skip transitions are accepted. A running task cannot start until every dependency is `succeeded` or explicitly `skipped`. Successful/explicitly skipped dependencies unlock downstream work in the same SQLite transaction. This state machine records work performed by MCP agents; it does not itself make model calls or claim scientific execution.

Evidence records require a source label, one of `supports`, `contradicts`, or `context`, an explicit quality annotation, and a JSON provenance object. Graph nodes and edges are scoped to a research session, and edge validation requires every evidence ID to belong to that same session. Legacy unscoped graph rows are migrated into a private legacy workspace rather than copied across sessions.

The graph API returns at most 500 nodes and 500 edges per request. Nodes and edges use independent keyset cursors ordered by `(label,id)` and `(source,relation,target)`, respectively, so consumers can page each collection without offset scans; exhausted-collection flags prevent rereading a finished collection while the other continues. MCP graph analysis and the workspace graph loader assemble pages only up to 50,000 records of each kind and fail explicitly when a full snapshot exceeds that operational ceiling. Interactive graph search runs as a bounded SQLite query and returns explicit node/edge truncation flags rather than downloading the full graph.

Evidence reads return at most 500 rows ordered by stable evidence ID. The first page captures a SQLite `rowid` watermark; later requests must carry both the last evidence ID and that watermark. This keeps a multi-page evidence snapshot consistent if a research session receives new evidence during pagination. API consumers should treat the watermark as opaque and MCP readers enforce a 50,000-record ceiling while assembling a full snapshot.

Evidence reads use the same bounded pattern: `/v1/research/{id}/evidence` returns at most 500 rows ordered by stable evidence ID, with `next_cursor` and `has_more`. MCP evidence listing and hypothesis/critic analysis assemble only session-matched pages and stop at 50,000 records rather than loading an unbounded collection.

Research reproducibility bundle schema v2 recomputes every retained artifact digest from the exact payload bytes before capture. It validates strict evidence provenance and finite descriptive quality annotations, then records SHA-256 digests of claim and provenance bytes while omitting their contents. Bundle import and diff verify the embedded canonical snapshot digest independently of the API artifact digest; readers continue to accept verified schema v1 captures. `bundle-diff` also maps changed artifact/evidence IDs to graph edges that explicitly reference them and flags those edges/endpoints for review, while refusing dangling references even when a bundle's unkeyed hash is recomputed. This is provenance impact triage only; it does not imply that a biological relationship changed.

Adding evidence or artifact provenance to an existing graph edge is additive and deduplicated; it never removes prior references. Edge confidence is immutable after creation because source-specific confidence belongs on separately retained assertion nodes. This keeps a graph edge from silently conflating confidence judgments made by different sources.

Research artifacts retain the producing task, original source name/record ID, session, JSON payload, capture time, and SHA-256 of the retained bytes. Only running tasks can record artifacts. Repeated identical source records deduplicate within a task; changed source contents remain as separately hashed revisions. Existing artifacts upgraded from older local databases are marked `legacy.unattributed` because their originating task cannot be recovered.

Research budgets are metered in execution credits. Starting a task costs one credit; bounded source operations and model-backed operations charge their configured costs, with model token charges based on provider-reported usage. Newly persisted artifact payloads are charged by complete MiB, isolated capability runners report measured process CPU for a rounded-up charge, and authenticated session-scoped API requests are charged before route execution. Charges and their task/reason are durable audit events. The API exposes remaining balance and charge history. System/provider/GPU compute, physical storage overhead, and sandbox runs killed before reporting a valid receipt remain outside the measured quota, so this is not a complete resource quota.

The API requires a bearer credential on all non-health routes when bound outside loopback. Credentials bind an opaque subject, role, and tenant; only token SHA-256 digests persist in SQLite, and tenant administrators can issue/revoke limited credentials for their tenant. Session routes, listings, summaries, recurring worker queues, quotas, and audit exports are tenant scoped. The Next.js workspace validates user credentials through `/v1/auth/me`, stores them only in an encrypted eight-hour `HttpOnly` browser cookie, and forwards them through a bounded same-origin proxy that checks `Origin` on mutations. The API rechecks role and tenant access on every request, and revoked credentials are cleared after an upstream 401. Compose publishes service ports on loopback. Platform administrators can set per-tenant active-session and credit budgets; service-level CPU/GPU, physical storage, and all internal API traffic are not fully metered.

Authenticated API request metadata, including exact tenant attribution when authenticated, is stored in a local SHA-256-linked audit chain. Tenant administrators can export their attributed rows as bounded NDJSON pages; full-chain verification is restricted to platform administrators and service credentials. Legacy rows without tenant attribution remain in the verifiable global chain and are excluded from tenant exports. An explicitly triggered retention policy archives a contiguous expired prefix to durable NDJSON before pruning database rows; persisted sequence/hash checkpoints let verification cover both archived files and live rows. The chain is not externally anchored.

## Capability lifecycle

`experimental → testing → validating → verified → production → deprecated`

The initial catalog record is metadata only. Promotion requires permission review, static/security checks, deterministic contract checks, a scientific benchmark with provenance, and an authorized reviewer. Production approval for a generated AgentMesh capability rechecks the persisted benchmark artifact, its session and payload hash, and its exact candidate proposal artifact and source digest against the immutable AMCP input bindings. Paired version benchmarks include an exact two-sided sign test over discordant pass/fail cases so small observed gains are not presented without their sample evidence; the test assumes independent cases and cannot correct benchmark selection or establish external validity. Stable repeated runs with an eligible measured improvement produce a structured human-review lead; benchmark results never change lifecycle state. Semantic capability reuse requires authenticated lifecycle, active AgentMesh route, compatible declared schemas/effects/permissions, and an operator-pinned holdout-passing calibration report. The schema comparator validates the supported schema subset, fails closed on malformed schema declarations and assertions it does not implement, and checks type containment in the input/output direction. Similarity and declared-contract fit still cannot establish behavioral or scientific equivalence; independently adjudicated task-capability calibration remains required.

## Confidence semantics

Keep evidence coverage, methodological quality, reproducibility, contradiction coverage, and novelty as separate fields with explicit computation and source sets. Never expose a single LLM self-rating as scientific confidence. Existing API quality values are manually supplied annotations; aggregation must not present them as statistically inferred probabilities.

## AgentMesh contract

`integrations/agentmesh/capabilities/biomedical.disease_research.yaml` is an AMCP `0.1` outcome contract. The registration script calls AgentMesh's own `capabilities validate` and `capabilities install` commands. Biomedical research DAGs are not mislabeled as Teach Workflow IR: AgentMesh Teach only accepts operations implemented by its runtimes. Expose research operations as MCP tools, then govern routing and access through AgentMesh.

The worker can persist a deterministic, versioned MedAI topology proposal from a session DAG in the reproducibility artifacts. It includes dependency validation and hash-only outcome receipts, and stays disabled until authenticated review. It is a MedAI domain artifact; it does not implement AgentMesh Teach Workflow IR or claim scientific validation.

## Storage evolution

SQLite supports a local single-user installation. A multi-user system needs tenant-scoped PostgreSQL, immutable object storage for datasets and paper artifacts, a graph store or indexed relational graph, and a vector index with source-level deletion and license tracking. Each adapter must preserve the same provenance and access contracts.

FASTA and FASTQ summaries retain per-symbol IUPAC nucleotide counts. Their `gc_fraction` remains G+C divided by all sequence symbols for compatibility; `gc_fraction_unambiguous` uses only A/C/G/T/U symbols. Reports name both denominators and separately expose ambiguity counts/fraction. Raw sequences and record identifiers are not retained.
